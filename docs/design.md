# Design notes

## 1. Scope

A digitally controlled synchronous buck on the DPOS G4 BUCK V2 board
(STM32G474CCU6, 12–48 V in, 22 µH, 5 A, 200 kHz), a CC/CV control loop, and
a serial shell with a 1 Hz telemetry monitor.  The OLED, USB and SPI2
functions were dropped by request; their pins are left unconfigured.

The vendor schematic and the unencrypted power examples P3 (CC/CV) and P7
(average-current double loop) were used as the hardware and loop reference.
The detailed control/tuning guide is in
[docs/digital_power.md](digital_power.md).
The assembled board uses an 8 MHz crystal even though the schematic says
12 MHz, and the schematic's USB-labelled header is not used by this firmware.

The original CubeMX output was unusable: `main.c` contained a FreeMarker
exception and truncated code, the TIM1 time base had no IRQ handler, and
`stm32g4xx_it.c` duplicated the FreeRTOS SVC/PendSV/SysTick handlers.  Those
files were rebuilt.

## 2. Clock tree

```
HSE 8 MHz ─ PLL (M=2, N=85, P=2, R=2) ─ 170 MHz SYSCLK
           (HSI 16 MHz fallback: M=4)
                                          ├─ AHB  /1 = 170 MHz
                                          ├─ APB1 /1 = 170 MHz  (USART2)
                                          └─ APB2 /2 =  85 MHz  (ADC2, TIM1)
```

Boost mode (`PWR_REGULATOR_VOLTAGE_SCALE1_BOOST`), 4 flash wait states.
The HAL 1 ms time base is TIM1 (APB2 timer clock 170 MHz, prescaler 169,
period 999).  FreeRTOS uses SysTick; the two are independent.

## 3. Power stage timing

| Item                  | Value                                   |
|-----------------------|-----------------------------------------|
| HRTIM clock           | 170 MHz, prescaler ×32                  |
| PWM period            | 27 200 counts = 5 µs = 200 kHz          |
| Repetition            | 1 → control ISR every 2 periods (100 kHz) |
| Outputs               | TA1 (PA8, HS), TA2 (PA9, LS)            |
| Set / reset           | set on PER, reset on CMP1               |
| Dead time             | 20 counts = 118 ns (rising and falling) |
| ADC trigger           | ADC trigger 1 = Timer A CMP3            |
| ADC sample instant    | CMP3 = CMP1 / 2 (middle of on-time)     |

CMP1/CMP3 are preloaded and updated on the master period, so a new duty is
applied without glitches.  TA2 is the complementary output generated by the
HRTIM dead-time unit.

## 4. ADC

ADC2 scans three channels on every HRTIM ADC trigger (rank order matters):

| Rank | Channel | Pin | Signal | Scale |
|------|---------|-----|--------|-------|
| 1 | ADC2_IN3 | PA6 | Vout | 3.3 V / 4096 × 17.5 |
| 2 | ADC2_IN2 | PA1 | Iout | 3300/4096 mV / 525 mV/A |
| 3 | ADC2_IN4 | PA7 | Vin  | 3.3 V / 4096 × 17.5 |

DMA1 channel 3, circular, half-word.  The control ISR keeps a four-sample
moving average.  Full-scale values: 57.75 V input/output, 6.28 A output.
The current-sense difference amplifier (U7D, 33k/2k, 0.03 Ω shunt) gives
about 495 mV/A; the vendor firmware uses 525 mV/A.  There is no bias on the
current channel, so 0 A reads 0.

Vin is kept: it is required for input UV/OV protection and is printed by the
monitor.

## 5. Control law

Incremental PI(D) in error form, same structure as the vendor P3 example:

```
e(k)  = setpoint - measurement
Δu(k) = Kp·(e(k)-e(k-1)) + Ki·e(k) + Kd·(e(k)-2e(k-1)+e(k-2))
u(k)  = clamp(u(k-1) + Δu(k), 0, 3.036)
duty  = u / 3.3
```

- Voltage loop: `vref - vout`, gains 0.10 / 0.001 / 0.50
- Current loop: `ilim - iout`, gains 0.11 / 0.001 / 0.50
- Applied duty is `min(duty_voltage, duty_current)`, clamped to 0.5–85 %
  - voltage loop controls in CV
  - current loop takes over in CC
- Soft start ramps `vref` at 1 mV per 10 µs tick (100 V/s); a setpoint
  decrease is ramped down at the same rate (5 V to 1.8 V takes about 32 ms)
  instead of stepping, so the output can follow.
- The OV limit uses `max(vref, vset) + 1.5 V` (capped at 40 V): during a
  downward setpoint change the limit follows the falling reference, so a
  normal voltage change cannot false-trip VOUT_OV.

The control path uses the FPU and direct HRTIM register writes; no HAL calls
or RTOS calls are made in the 100 kHz ISR.  `app_power.c` is compiled with
`-O2` even in Debug so the ISR stays well inside its 10 µs budget.

A Python averaged-plant simulation of this loop (12 V in, 5 V out, 22 µH,
470 µF, 1 A → 2 A load step) settles at 5.000 V without overshoot; duty stays
at Vout/Vin in CV.

## 6. LED indication

The RGB LED is updated from the control ISR with a 10 ms time base
(100 kHz / 1000), active low:

| LED | Meaning |
|---|---|
| Blue | 2 Hz heartbeat in every state (100 ms on) |
| Green | steady while the output is enabled (`SOFT_START` or `RUN`) |
| Red | steady while a fault is latched |

CV/CC is still computed from the loop arbitration and exposed in the
telemetry (`RUN (CV)` / `RUN (CC)`, `/CV` / `/CC` in `monitor`), but the LED
no longer differentiates it.  Blue is driven purely by the time base, not by
the converter state, so it keeps blinking after `poweron`.

## 7. Protection

| Fault | Threshold | Action |
|-------|-----------|--------|
| VIN_UV | Vin < 10 V | latch, outputs off |
| VIN_OV | Vin > 50 V | latch, outputs off |
| VOUT_OV | Vout > min(max(vref, vset)+1.5 V, 40 V) | latch, outputs off |
| IOUT_OC (sustained) | Iout > ilim+0.5 A for 2 ms | latch, outputs off |
| IOUT_OC (software fast) | filtered Iout > 6 A immediately | latch, outputs off |
| PEAK_OC (hardware) | COMP3 peak > DAC1 threshold (≈7 A) | latch, outputs off in µs |

Outputs are disabled through `HRTIM1->sCommonRegs.ODISR`, which acts
immediately and independently of the PWM period.  The fault is latched and
reported by `status`; `reset` stops the output and clears it.

`Power_EmergencyStop()` is also called from `Error_Handler()`, the hard/memory
fault handlers and the FreeRTOS stack-overflow/malloc hooks so a firmware
failure does not leave the bridge switching.

The hardware peak path is COMP3 + DAC1: PA0 is `I_PEAK_DETC` (U7A, ≈222 mV/A),
DAC1_CH1 sets the threshold (≈7 A), and the comparator EXTI sets `PEAK_OC`
and disables the outputs independently of the ADC/control loop.  See
[docs/digital_power.md](digital_power.md) for the threshold calculation and
test procedure.

## 8. RTOS layout

| Context | Priority | Period | Work |
|---------|----------|--------|------|
| HRTIM1_TIMA IRQ | 2 (preempt) | 10 µs | ADC read, CC/CV loop, protection, telemetry |
| USART2 IRQ | 6 | per byte | push into 256-byte ring buffer |
| TIM1 IRQ (HAL tick) | 15 | 1 ms | `HAL_IncTick()` |
| SysTick (FreeRTOS) | 15 | 1 ms | kernel tick |
| shell task | 24 | 10 ms | line editing, commands, 1 Hz monitor |

The control ISR never calls a FreeRTOS API.  Telemetry crosses the ISR/task
boundary through a seqlock, so readers always get a consistent snapshot
without disabling interrupts.  FreeRTOS heap is 8 KB and the shell task
stack is 2 KB.

## 9. Shell implementation

- USART2 115200 8N1, interrupt RX into a single-producer/single-consumer ring
  buffer; the task polls every 10 ms.
- Only the shell task transmits, so no UART mutex is needed.
- Line editing: echo, backspace, CR/LF handling (a CRLF pair counts as one
  line), a 10-entry up/down command history, and Tab completion of command
  names.  ANSI escape sequences are consumed so arrows do not leak into the
  line buffer.
- All numeric output is integer/fixed-point; newlib float printf is not
  linked.
- `monitor` starts a 1 Hz stream of
  `Vin=… Vout=… Iout=… Pout=… STATE D=…`, generated from the telemetry
  snapshot.  While the stream is active the prompt is suppressed; `q` is a
  single-key hotkey (no echo, no Enter) that restores the prompt.  There is no `monitor off` command.
  Other commands remain usable while streaming.
- The Vin/Vout/Iout scaling gains are compile-time constants in
  `app_config.h` (`CAL_VIN_GAIN` 0.985, `CAL_VOUT_GAIN` 0.94,
  `CAL_IOUT_GAIN` 1.0).  They are applied inside the 100 kHz loop, so the
  voltage loop, protection and telemetry share the same scaling.  There are
  no runtime calibration commands; `status` prints the active gains.  The
  nominal schematic divider is 17.5:1; the measured board needed about 0.94
  on Vout (roughly 16.45:1) and 0.985 on Vin.

## 10. Verification performed

- Clean Debug and Release builds with `-Wall`, no warnings.
- Linker map: about 62 KB flash / 18 KB RAM (Debug) and 39 KB / 18 KB
  (Release).  The 8 KB FreeRTOS heap dominates the RAM figure.
- Interrupt vector table checked: SVC/PendSV/SysTick resolve to the FreeRTOS
  port and CMSIS wrapper, TIM1 update, USART2 and HRTIM1 Timer A resolve to
  the application handlers.
- Control loop simulated on the host over start-up, CV/CC load steps and
  hard-short protection.

Not verified without hardware: ADC offset/gain of the actual board, gate
driver dead-time margin, conducted EMI and thermal behaviour.  The measured
board gains are baked into `CAL_VIN_GAIN`, `CAL_VOUT_GAIN` and
`CAL_IOUT_GAIN`; start with a current-limited supply.  See
[docs/digital_power.md](digital_power.md) for the tuning procedure and
[docs/build-and-flash.md](build-and-flash.md) for build/flash details.
